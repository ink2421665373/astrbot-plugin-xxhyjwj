# 永劫无间战绩查询

**当前版本：1.9.6**（更新内容见 [CHANGELOG.md](CHANGELOG.md)）

适用于 AstrBot 4.29.0-beta.1 及以上版本与 QQ（aiocqhttp）的永劫无间**端游**战绩插件。
按昵称查询小黑盒中的近期对局、单局详情和赛季总览。
数据来自小黑盒的非公开接口，使用前需由管理员扫码登录小黑盒（无绑定模式除外）。

项目地址：[ink2421665373/astrbot-plugin-xxhyjwj](https://github.com/ink2421665373/astrbot-plugin-xxhyjwj)。
基于 [as124da1231/astrbot_plugin_naraka](https://github.com/as124da1231/astrbot_plugin_naraka) 修改，保留原作者信息及插件标识 `astrbot_plugin_naraka`，继续使用原有配置和数据目录。

## 数据模式

插件有三种数据模式，在配置页的「数据模式」里三选一：

| 模式 | 登录方式 | 可用能力 |
| --- | --- | --- |
| `heybox`（默认） | `/永劫登录` 发**小黑盒 App 二维码** | 全量查询（战绩/详情/赛季）+ 自动绑定兜底 |
| `wechat` | `/永劫登录` 发**微信扫码二维码** | 与 `heybox` **完全等价**，只是扫码渠道不同 |
| `none` | **不需要登录**，`/永劫登录` 会提示无需登录 | 只走免登录接口：免登录搜索、战绩查询退化为「角色名片」（昵称/角色ID/服务器/境界/总积分/场次） |

`wechat` 与 `heybox` 的角色绑定能力相同——绑定解绑与扫码渠道无关。

## 查询主流程

```
战绩查询 昵称
  ├─ 搜到了   → 更新数据 → 取列表 → 按配置决定是否取单局详情 → 返回
  └─ 没搜到
       ├─ 绑定「昵称」→ 轮询绑定结果
       │    ├─ 绑好了   → 重新搜索（这次能搜到）→ 更新 → 取数据 → 返回
       │    │              → 查完立刻解绑
       │    └─ 没绑好   → 「绑定失败：<原因>」
       └─ 绑定成功但查询失败 → 「绑定成功，查询失败：<原因>」
```

* 绑定用的是**你输入的原始昵称**，不做任何纠偏；所以大小写/空格不精确时会绑定失败（失败只是拿不到数据，不会绑错人）。
* **一次只能绑定一个号**：绑定是全局互斥的，但纯只读查询不受影响。
* 解绑在查询结束后**无条件执行**；绑定结果为 `waiting` 超时也会尝试解绑。
* 解绑失败会提示：`昵称 解绑失败，请发送：战绩解绑 昵称`——任何人都可以执行这条指令自行收尾。

## 指令

除管理员登录外，其余指令都可以作为普通消息直接发送，不需要 `/` 或其他唤醒词；带 `/` 的写法同样兼容。

| 指令 | 功能 |
| --- | --- |
| `战绩查询 <昵称> [模式] [强制刷新]` | 排位/天人分数、近期有效对局数、常用英雄和场均伤害、振刀、击败；搜不到会自动走绑定兜底 |
| `详细查询 <昵称> [模式] [强制刷新]` | 有效对局逐场列出英雄、击杀、伤害等；恢复、振刀、存活等字段取决于单局详情查询方式 |
| `战绩分析 <昵称> [模式] [强制刷新]` | 调用AstrBot已配置的聊天模型和人格，评价本次战绩 |
| `战绩绑定 <昵称> [模式]` | 跳过只读尝试，**强制**走「绑定 → 查询 → 解绑」通道 |
| `战绩解绑 <昵称>` | 手动解绑（**任何人可用**）；昵称与绑定时一致 |
| `永劫搜索 <昵称>` | 搜索玩家；**免登录**，未登录也能用 |
| `永劫赛季 <昵称> [模式] [当前/全部/赛季名]` | 查看某模式的赛季总览；内容过长时分条发送 |
| `/永劫登录` | 管理员按当前数据模式扫码登录 |
| `/永劫退出` | 管理员清除本地登录凭证 |
| `/永劫残留` | 管理员查看并重试解绑残留（进程被 kill 后的兜底） |

> **不支持按角色ID查询。** 输入看起来像角色ID时会明确提示改用昵称。
> 所有查询结果的首行都会同时给出昵称和 ID，例如 `昵称：<昵称>｜ID：<角色ID>`，
> 方便你对上号——但那一串 ID 不能拿回来查询。

模式写法（全部等价）：

```
单排 / 双排 / 三排                     ← 固定归到「天选」
天选单排 · 天选双排 · 天选三排
天人单排 · 天人双排 · 天人三排
天选之人三排 · 天人之战单排 · 快速匹配三排   ← 长写法兼容
快速单排 · 快速三排 · 无尽试炼
4 / 13 / 5 / 5000000 / 12 / 5000001 / 6 / 7 / 5000010   ← 原始 battle_tid
```

不指定模式时，插件先读取按时间排序的混合对局，排除快速等非排位模式，再按最新一场排位对局选择模式。

## 自然语言调用（LLM 工具）

除了上面的指令，插件还会把核心能力注册成 AstrBot 的 `llm_tool`（函数工具）。开启后**不用记指令**，直接在对话里用自然语言说就行，由大模型判断并调用对应工具：

| 自然语言示例 | 实际调用的工具 | 作用 |
| --- | --- | --- |
| 「查下张三最近打得怎么样」 | `naraka_query_summary` | 近期战绩场均概览 |
| 「张三最近几场分别什么数据」 | `naraka_query_detail` | 逐场战绩明细 |
| 「搜一下叫张三的玩家」 | `naraka_search_player` | 免登录搜索玩家（核对昵称） |
| 「张三这赛季什么段位」 | `naraka_season_stats` | 赛季总览 |
| 「评价一下张三的战绩」 | `naraka_ai_analysis` | AI 战绩评价 |
| （默认关闭）「把张三解绑」 | `naraka_unbind` | 解绑，带副作用 |

### 开启步骤

1. 插件配置里 **`enable_llm_tools` 保持为 `true`**（默认即开启）；想彻底不注册工具就关掉它。
2. 在 AstrBot 的**会话设置或人格（Persona）里启用「工具调用 / Function Calling」**，并确保所用模型支持工具调用。
3. 重载插件，直接在群里问「某某最近战绩怎么样」即可。

### 与指令的关系

- 战绩类工具（概览/明细/赛季/AI 评价）在「战绩显示格式」为**图片**时，会**先把同一份长图直接发到会话**，再把文本作为工具结果交给模型——所以自然语言和指令一样能看图。想只回文字，把 `llm_tool_send_image` 关掉，或把显示格式设为文字。
- 工具复用和指令**完全相同**的保护逻辑：群白名单、查询冷却、`_query_lock` / `_ai_lock` 并发互斥、自动绑定兜底。
- 回传文本长度受 `llm_tool_max_text_chars` 限制（默认 4000 字），超出会截断并提示改用指令看完整结果，避免把模型上下文打爆。
- 一次自然语言查询实测要跑几十秒上游接口，这期间模型不会说话。所以工具在开始查之前会先回一条 `llm_tool_notice_text`（默认「正在翻 {nickname} 的战绩，请稍等…」，`{nickname}` 会换成这次的玩家昵称；拿不到昵称时用 `llm_tool_notice_fallback`；随 `llm_tool_start_notice` 开关），等超过 `query_progress_wait_seconds`（默认 15 秒）还没好，再补一句「查询仍在进行，请稍候；完成后会发送结果。」。同一条消息只回执一次。
- `naraka_unbind` 是**写操作**且有副作用，需要额外把 `llm_tool_allow_unbind` 设为 `true` 才会暴露给模型（默认 `false`）。
- 关掉 `enable_llm_tools` 不影响任何原有指令，二者互不干扰。

### 别让其它插件把永劫消息当成剑三

如果同一个机器人还装了剑三战绩插件，它会在发问前做一次「提示注入」：只要消息里出现「战绩」「排行」这类通用词，就往用户 prompt 末尾拼一句「（内部提示：这是剑三数据查询，必须调用 mingjian_query 工具…）」，还会在会话上留一个强制补调标记。结果是模型把「查某某的永劫战绩」当成剑三来答，甚至开始自言自语。

本插件默认开启 `llm_tool_strip_foreign_hints`，用一个排在它之后的 `on_llm_request` 钩子（`priority=-100`）做三件事：删掉那段注入文本、删掉 system prompt 里提到 `mingjian_query` 的段落、清掉那个强制补调标记，再补一句「本条属永劫无间，只用 naraka_* 工具」。

判定只看**游戏专有名词**，不看共享词：

- 判永劫：`永劫`、`无间`、`naraka`、`振刀`、`魂玉`、`聚窟州`、`天人之战`、`天选之人`、`双排`、`三排`，以及英雄名；另外，消息里出现「昵称与角色」面板登记过的昵称也算。
- 判剑三：`剑网`、`剑三`、`名剑`、`奇穴`、`心法`、`图谱`、`组排`、`散排`、`竞技场`、`pvp`、`jjc`，以及 `22/33/55`、`2v2/3v3/5v5`。
- `单排`、`战绩`、`排行`、`强度`、`段位` 这些两边都在用的词**不参与判定**：分不出游戏时，插件不会删掉剑三的提示（可能真是剑三在问），而是把它**改写成中性说法**——「如果问的是永劫就用 `naraka_*`，问的是剑三就用 `mingjian_query`，不要自行假设」，同时清掉那个会强制补调剑三工具的标记。两个游戏都不会被误导。

彻底的办法是人格里的工具白名单：哪个群只玩永劫，就在该群的人格「工具」里只勾 `naraka_*`——剑三插件拿不到自己的工具，根本不会注入提示。

### 昵称 ↔ 角色唯一标识

「张三」「老王」这类称呼在游戏里并不唯一，模糊搜索经常搜到同名玩家。可以在面板里把昵称和一个**唯一角色ID**固定绑定，之后无论用指令还是自然语言，都直接按这个 ID 查，不再猜。

**一个角色可以挂多个昵称**：常用叫法、曾用名、带符号的写法、大小写变体都能登记在同一个角色ID下，任意一个命中都定位到同一个角色。

打开 AstrBot WebUI → 插件 → 永劫无间战绩查询 → 插件详情 → Pages/页面 → **「昵称与角色」**：

1. 在上方输入框填昵称，点「解析并添加昵称」。插件走**免登录搜索**拿候选；精确同名优先，重名时列出候选供你点选。
2. 解析出的 `角色ID` 会自动写入表格并**只读显示**（灰底不可编辑），改错会查到别的角色。
3. 该角色已经在表里时，新昵称会作为**标签**追加到同一行；也可以直接在那一行的虚线框里手打昵称（回车生效），不必再解析一次。
4. 点标签上的 `×` 移除单个昵称（每行至少保留一个）；点该行「删除」移除整个角色。
5. 需要时点「保存全部修改」。保存走版本号校验，多人同时编辑会提示冲突。

| 输入 | 效果 |
| --- | --- |
| 指令：`战绩查询 张三` | 命中映射 → 直接用登记的 role_id 查 |
| 指令：`战绩查询 老三`（同一角色的另一个昵称） | 同样命中 → 同一个 role_id |
| 自然语言：「张三最近打得怎么样」 | 同上，LLM 工具共用同一解析入口 |
| 未登记的昵称 | 仍走原来的搜索 + 绑定兜底逻辑 |

要点：

- 昵称按**归一化**匹配：忽略大小写、首尾空格与零宽字符，所以「张三」「 张三 」「ZhangSan」视为同一条；同一个昵称只能属于一个角色，重复会被拒绝。
- `role_id` 是小黑盒的 `game_id`：**字母数字混合的 22 位串**（如 `2i67000021275100070163`），不是纯数字，最长 64 位；整个表最多 500 行。
- 配置文件里仍是**一行一个昵称**（`nickname_mappings`），多个昵称就是同一 `role_id` 的多行；面板负责按角色聚合展示，手动改配置文件同样有效。
- 映射**只解决「查谁」，不解决登录态**：战绩、赛季这类需要登录的请求，仍要求已登录小黑盒。
- 数据在插件配置 `nickname_mappings` 里，和面板共享同一份；备份配置即备份对照表。
- 映射命中时不会发起任何搜索请求，查询更快也更稳定。

#### 侧边栏为什么看不到这个页面

AstrBot 左侧边栏默认是**扁平模式**，每个插件只占一个入口位，且固定取按目录名排序后的第一个视图。本插件排序结果是 `diagnostics` → `mappings` → `nicknames`，所以在默认模式下侧边栏只会出现「数据诊断」，「英雄与赛季」和「昵称与角色」都不在其中——**不是页面缺失，也不是缓存**。

两个解决办法，任选其一：

- **推荐：开启侧边栏的分组显示。** 点侧边栏「扩展功能」标题附近的网格图标按钮（悬停提示「按插件分组」），开启后每个插件变成一个可折叠分组，三个视图全部列出。该开关记在浏览器 localStorage（`sidebar_group_by_plugin`），设一次即长期有效。
- 或者每次从插件详情页进入：插件卡片 → 插件行为 → 页面 → 选择视图 → 打开。

页面目录是**请求时实时扫描**的，所以安装或更新视图后只需刷新浏览器，不必重启 AstrBot。

## 配置

### 英雄与赛季可视化管理

赛季页会显示数据模式、登录文件状态和本地凭证是否载入，并提供「刷新登录状态」。进入页面、刷新状态和同步前都会重新读取本插件的登录文件，更新请求客户端；仅返回状态摘要，不返回凭证。如果模式为 `none`，需要在插件配置切换为 `heybox` 或 `wechat` 并保存重载，已有登录无需重复扫码。文件缺失、为空、格式错误和读取失败分别提示；本地有凭证并不代表已通过小黑盒在线校验。

更新并重载插件后，在 AstrBot WebUI → 插件 → 永劫无间战绩查询 → 插件详情 → Pages/页面（新版称可视化视图），打开「英雄与赛季」。页面使用 beta.1 与新版共同支持的 `pages/` 目录，兼容 `AstrBotPluginPage` 和 `AstrBotPluginView` bridge，不需要另开端口或单独登录。

- 英雄页：搜索编码或名称，新增、修改、删除英雄对照。支持两位编号和完整英雄 ID，原有配置会保留。
- 赛季目录：在赛季页输入一个可直接查询的玩家昵称，选择模式，点击「从接口同步全部赛季」。复用机器人已保存的小黑盒登录状态，读取主页接口的完整 `seasons` 列表并自动保存；不需要复制编码逐项添加。已有未保存修改时，请先保存或重新载入。普通战绩查询取得的赛季目录也会自动收录；页面打开期间有新的收录时，点击重新载入可查看。
- 同步按编码去重并补充所有新条目，保留手动名称、查询赛季选择及上游暂时未返回的已有条目。同步显示接口项数、有效目录数、新增数和无效条目数；接口失败或空列表不会清空现有配置。选择 `pre-01 / 全部` 后查询全部赛季，文字和图片显示“全部赛季”，不再将其映射为当前赛季。兼容之前保存的选择，无需重新勾选。
- 赛季页：填写真实赛季编码和名称，勾选一项「用于查询」，再点击「保存全部修改」。勾选本身不会影响机器人查询，页面会区分未保存选择和已保存范围。保存后的选择同时控制赛季概览、六模式分数、近期对局列表及其翻页，详细查询和AI分析也使用该赛季。直接按所选编码请求，不先访问全部赛季目录；所选赛季的列表或主模式概览请求失败时，本次自动回退到全部赛季一次。回退会重新读取全部赛季列表和概览，避免混用范围，不修改WebUI选择。一次查询固定使用发起时的选择，期间保存的新选择从下一次查询生效。
- 手动选择的报告显示「指定赛季概览」，名称带有「WebUI配置」标识；选择 pre-01 / 全部时仍为「全部赛季概览」，不把历史或全部数据宣称为游戏当前赛季。点击「恢复接口自动识别」并保存，可清除手动选择。指定赛季名称或编码的查询也支持手动配置的条目。
- 两页统一点击「保存全部修改」，只保存英雄、赛季字段；其他插件设置不变。页面跟随 WebUI 亮暗主题，保存冲突和校验错误会明确提示。

赛季编码不预置猜测值，优先使用页面同步。同步需要已登录的小黑盒模式，且昵称能直接唯一匹配；此操作不会自动绑定角色。也可发送 `永劫赛季 昵称 双排 列表` 查看真实选项；如果新赛季不在接口目录中，需要从可信的实际接口响应获取编码后补充。同步“全部”指该接口返回的完整目录，不保证包含上游尚未开放的新赛季。配置映射不代表小黑盒一定支持该编码；请求失败时按下述规则回退。
普通插件配置页也保留英雄、赛季的模板列表，与可视化视图共享同一份配置。两个页面同时修改时，请重新载入最新值后再保存。

开发接口参考：[AstrBot v4.29.0-beta.1 Pages 文档](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.0-beta.1/docs/zh/dev/star/guides/plugin-pages.md)与[v4.29.1 可视化视图文档](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.1/docs/zh/dev/star/guides/plugin-pages.md)。新版保留 `pages/` 兼容入口；只提供一份页面目录，避免重复入口。`tests/preview_mapping_view.py` 仅是本地模拟 bridge 的预览服务器，不由插件启动。

### 赛季识别与诊断

发送 `永劫赛季 昵称 双排 列表` 可查看接口返回的完整赛季名称、原始 ID 和选择标记，长列表分条发送。未知赛季报错也会列出全部选项，不再只展示前八项。此诊断结果固定使用文字，便于复制。
未设置手动当前赛季时，自动选择「当前」只接受唯一的 `is_current` 或 `current` 真值，不把 `selected` 或列表位置当作当前赛季。无法确认时明确提示，仍保留战绩查询的近期统计；不猜测未公开的新赛季 ID，也不以全部赛季替代当前赛季。根据官方结算公告，2026-10-09 08:00（北京时间）之后不再把千机赛季认作当前赛季，指定「千机」仍可查历史数据。
若列表没有可匹配的新赛季项，只能确认该查询返回的选项无法选择该赛季；这不等于已证明小黑盒所有接口都不支持新赛季。需要结合完整列表和实际返回继续定位。

启用单局详情时，还会展示钩索使用与命中、招式命中、技能释放、救援、复活数、移动距离、消耗货币、武器占比与伤害、魂玉和标签。

`战绩查询` 还会展示所选模式的当前赛季概览：赛季名称、分数、段位、等级，以及接口 `overview` 实际返回的全部有效指标。近期对局汇总单独标注统计范围。赛季数据失败或不可用时明确提示，不以全部赛季或近期统计替代。结果过长时分条发送。近期没有所选模式对局时，可显式指定模式查询赛季数据。

三个间隔各管一段，互不叠加：

* **A（用户请求间隔）** 只防"多人反复发起"，**独立**于 B/C，不延长一次查询本身。
* **B（机器人请求每项间隔）** 覆盖机器人发出的**每一次**上游请求：搜索、绑定、状态轮询、更新、对局列表、单局详情、解绑。
* **C（仅单局查询之间间隔）** 只管**相邻两次单局详情**；B 包含 C，所以详情之间的实际间隔取 `max(B, C)`，**不是相加**。

三者都可以设 `0` 关闭对应固定间隔。新配置默认 `A=4 / B=1.5 / C=4`，旧配置的B=0不会被覆盖；限流后的暂停保护独立生效。B增大会增加整次查询耗时，但可避免搜索、更新和六种模式概览连续密集请求。

检测到业务限流或HTTP429后，停止后续查询请求，默认本地暂停60秒；期间聊天查询和WebUI同步会提示等待，不继续访问接口、不自动重试、不因重复查询延长保护。HTTP429支持Retry-After秒数和HTTP日期，按[HTTP规范](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)解析。暂停只是本地保护，上游实际限制的维度和恢复时间不能从错误提示中确定。若临时绑定尚未解绑，会保留残留记录供后续恢复；解绑遭限流时停止快速重试。

再次遇到限流时，日志会记录`upstream rate limit: path=接口路径; local_pause=秒数`，不打印昵称、ID或凭证。可据此区分搜索、更新、列表、详情与概览阶段；这条日志不代表已确定上游限流的账号或网络维度。

## 行为边界

* 搜不到昵称 → 提示用 `永劫搜索` 核对（搜索是独立指令，插件不会替你发）。
* **输入像角色ID → 明确提示「不支持按角色ID查询」，不会去搜索、也不会触发绑定。**
* 同名玩家 → 要求先用 `永劫搜索` 查看玩家，避免查错人。
* 命中限流或登录失效 → 停止后续请求并明确提示原因。
* 无绑定模式下，`详细查询` 和 `永劫赛季` 会提示该模式不支持，而不是回一堆空数据。

保存了WebUI赛季选择时，战绩查询、详细查询和AI分析先按同一赛季编码请求。所选赛季的对局列表或主模式概览请求失败时，本次改查全部赛季一次，重新获取全部赛季的列表和概览，再生成统计和详情；文字、长图和AI证据均显示回退说明及实际赛季范围，不把全部数据称为所选赛季。回退不修改配置，不会循环重试；已经在查全部赛季时不会再次回退。

正常返回0场、局部详情缺失、其他模式分数缺失均不等于整个赛季查询失败。限流或登录失效时停止请求，不通过切换赛季重试。配置校验错误也会直接提示。近期对局仍按模式筛选，可能出现概览有数据但近期选中0场。

未选择WebUI赛季时保留自动识别：近期对局请求全部赛季，概览尝试识别当前赛季；如果目录缺少唯一当前标记或仍指向已结束的千机赛季，才展示已成功返回的全部赛季概览并说明范围。登录、限流及网络异常不会伪装成成功回退。发送“永劫赛季 昵称 模式 当前”使用WebUI选择；明确发送“全部”或其他赛季名/编码则按该命令指定的范围查询。

指定单/双/三排时，列表请求携带对应模式，不再一律发送天选双排编码12；翻页保持同一模式。接口仍可能返回混合列表，因此继续按每条记录的battle_tid筛选，不把其他模式凑作所选模式。选中0场时会列出实际返回的模式分布，未知编码单独标注。省略模式时保留原有列表请求方式，再从实际返回的记录中选择模式。

### 天人之战段位名称

天人之战与天选之人使用不同的段位体系。[端游2025年7月24日公告](https://www.yjwujian.cn/news/update/20250710/33456_1246358.html)确认天人段位名称单独调整；[2026年千机赛季结算公告](https://www.yjwujian.cn/news/update/20261010/33456_1316200.html)仍将天人的“星月宗师”与天选的“蚀月、坠日、修罗”等分别说明。

战绩查询、赛季查询、文字、图片和AI证据共用校验：天人单/双/三排中，若接口的段位名称含天选称谓，则不将其当作天人段位展示，标注“段位：待确认”，保留接口分数、等级和其他统计。概览中的最高段位等名称也会检查；段位积分等数值保持原样。接口原始响应不被修改，天选查询不受影响。接口正确返回的天人名称及历史称谓仍按原值显示。

这项修复防止混用名称，不提供未经核实的完整积分换算表。上述端游公告没有给出完整的新名称与分数对应关系，不能直接套用手游4500分起的规则或旧版“大师/宗师”表。接口只给编码或不适用的名称时，AI也不得自行按积分补算。赛季查询若明确返回其他模式的数据，会直接提示模式不一致。

### 管理员数据诊断

- 区分返回零值、未返回指标、缺少 value 字段、null、空值和字段格式异常。接口原始名称不套用自定义映射；selected 不作为当前赛季的证明。
- 不额外访问小黑盒；仅从更新后的实际请求自动采集。历史请求无法补录，详情缓存命中不会产生新记录。请求错误只保留固定类别，不保存异常原文。
- 最近50次主页/单局请求摘要仅保存在内存中，可清空，重载插件后丢弃。目录最多保留500项、指标最多保留200项，超出时显示截断提示，不影响原战绩查询。
- 仅保留允许的诊断字段，不返回登录凭证、玩家昵称、角色ID、对局ID、请求签名或原始响应；指标值仅展示数字及单位等数值形式。通过 AstrBot WebUI 的插件 API 访问，不在公开聊天指令中输出。

查询结果显示查询发起时间，统一使用北京时间（UTC+8）。近期样本时间范围只取本次选中模式及场次的对局列表时间，包含详情请求失败的选中对局；部分时间缺失时标明有有效时间的场数，范围仅覆盖这些对局。没有有效时间时显示未知，不用其他模式或全部历史记录的日期代替。

当前没有已核实的数据更新时间字段，结果明确显示“数据更新时间：未知（不以查询时间代替）”。查询时间、对局时间和接口数据更新时间分别处理；详细查询的逐局时间也统一使用北京时间。赛季查询和赛季列表显示查询时间及数据更新时间状态，不将近期样本范围当作赛季统计范围。

### 查询进度、强制刷新和原图文件

- 默认使用安静进度：15秒内完成不发送进度，超过15秒最多追加一次“查询仍在进行”提示。完成、失败或取消时停止等待提示，避免结束后迟到消息。可在WebUI的“显示查询等待提示”“查询进度模式”“查询等待提示阈值”中调整或关闭；手动选择详细进度后，所有阶段及场次消息统一受间隔限制，阶段切换不能绕过。已有开关和详细进度间隔设置保留；未设置新模式时默认安静模式。收到请求立刻回执是独立设置。
- 在查询末尾加“强制刷新”（也支持 --refresh），如“详细查询 昵称 双排 强制刷新”。会请求上游更新，并绕过本次选中对局的旧详情缓存；详情查询仍受“单局详情查询方式”控制，冷却和请求间隔继续生效。刷新失败不会继续使用本次绕过的旧详情。上游更新请求不保证即时完成，数据更新时间仍按未知处理。
- 管理员在插件详情 → 可视化视图 → 数据诊断 → 战绩缓存中查看缓存数量并清空；查询进行中禁止清空，避免影响在途请求。清空仅删除内存中的单局详情，不影响登录、英雄/赛季配置及诊断记录。
- “图片结果附带原图文件”默认关闭。开启后，先发送完整长图，再通过 AstrBot File 消息发送相同PNG字节，不再次绘制。文件功能依赖实际平台和适配器支持；跨容器/跨主机部署可能需要AstrBot文件回调或共享路径。文件发送失败会明确提示，已发送的图片保留。
- 原图临时保存在插件数据目录 original_images 下，超过24小时的本插件PNG在下一次发送原图时清理，避免异步文件下载期间提前删除；不开启附件时不会写入原图文件。
- 图片生成失败自动分条回退文字，每条最多1200字符，超长单行也拆分，完整保留内容，at回复只在首条添加。

### AI战绩分析

1. 在AstrBot中正常配置聊天模型，并创建想使用的人格。
2. 打开本插件的“配置”，找到“启用AI战绩分析”“AI分析聊天模型”和“AI分析人格”。模型与人格使用AstrBot原生选择器，直接选择已有配置，无需再次填写API地址或密钥。
3. 发送“战绩分析 昵称 [模式]”，例如“战绩分析 冷门男明星 双排”。支持末尾加“强制刷新”或“--refresh”，冷却及请求间隔继续生效。
4. “战绩分析”会保留完整原始战绩并在末尾追加AI评价，方便核对分析依据。“普通查询后自动分析”默认关闭。开启后，战绩查询、详细查询及战绩绑定也会追加评价；文字输出分条，图片输出保持一张长图。关闭时只有战绩分析指令调用模型。

模型留空时使用当前会话的聊天模型。人格留空时解析当前会话的有效人格（包含会话/群规则）；明确选择后仅用于本插件分析，不改变正常聊天配置。使用人格系统提示词，不携带聊天历史，不执行人格工具或技能。分析请求不会触发第二次默认聊天模型回复。

评价依据本次查询已获取的数据，不重复请求战绩接口，不传登录凭证、玩家昵称、角色ID或对局ID给模型。将近期数据与全部/指定赛季数据分开，并明确每项指标的数据覆盖场数；缺失不是零，查询时间不代表更新时间。模型仍可能误读数据，AI段落单独标注为参考评价。

近期样本最多读取“查询对局数”场（默认30场，以接口实际返回为准），请求携带所选模式，再逐条校验返回记录的模式；上游返回混合列表时仍会筛选。因此“选中0场”不代表该模式没有历史战绩。报告会注明实际读取/选中场数及空样本时的模式分布；如果仅取得概览，AI只评价概览，不评价近期表现。回退到全部赛季时，也会将数据范围传给模型。未请求详情、详情失败和列表为空会分别说明，不能因数据缺失责怪玩家。需要扩大近期筛选范围时可增加“查询对局数”，实际可获取范围仍取决于接口分页，且查询可能变慢。

近期汇总使用全部有效记录；默认最多向模型携带10场明细，最多50场，可在WebUI调整。输入证据默认12000字符预算，超出时减少AI输入中的明细和部分概览，不删减原战绩。人格系统提示词不计入该预算，仍需符合所选模型上下文限制。默认超时60秒，可调整。

模型或人格失效时明确提示，不悄悄换成其他模型或人格。超时、空响应或调用失败时保留原始战绩并显示原因，不展示服务错误原文；临时绑定的账号会先解绑再等待AI分析。分析共用安静等待提示，默认短查询不提示，长查询最多追加一次提示。

通过自然语言触发AI评价时（工具 `naraka_ai_analysis`），走的是同一套人格与证据预算规则，但结果以工具回传文本交回模型，不再另行在群里发一条分析消息。

### LLM 工具相关配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enable_llm_tools` | `true` | 总开关，是否把战绩能力注册为 `llm_tool` 供大模型调用 |
| `llm_tool_allow_unbind` | `false` | 是否把带副作用的解绑工具 `naraka_unbind` 也暴露给模型 |
| `llm_tool_max_text_chars` | `4000` | 单个工具回传给大模型的最大字符数（下限 500），超出截断 |
| `llm_tool_send_image` | `true` | 自然语言调用时是否也把战绩长图发到会话（仅在显示格式为「图片」时生效） |
| `llm_tool_strip_foreign_hints` | `true` | 清理其它插件误注入到请求里的提示（如剑三插件拼进用户 prompt 的「这是剑三数据查询」），只对明确属于永劫的消息生效 |
| `llm_tool_start_notice` | `true` | 自然语言查询开始前先回一条短提示，避免几十秒没反应 |
| `llm_tool_notice_text` | `正在翻 {nickname} 的战绩，请稍等…` | 回执文案，支持 `{nickname}` 占位符；留空则关闭回执 |
| `llm_tool_notice_fallback` | `正在查战绩，请稍等…` | 文案里有 `{nickname}` 但拿不到昵称时改用这一条 |
